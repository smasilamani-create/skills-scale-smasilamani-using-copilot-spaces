# OctoAcme Project Management Docs

Welcome to the OctoAcme project management documentation hub. These docs standardize how we run projects to ensure clarity, consistency, and alignment across all teams.

## Quick Start for New Team Members

Start with: **[OctoAcme Project Management Overview](octoacme-project-management-overview.md)** — Get oriented with our core principles, roles, and lifecycle.

## Documentation by Project Lifecycle Phase

### 1. Initiation
- **[Project Initiation Guide](octoacme-project-initiation.md)** — Validate business need, align stakeholders, decide go/no-go
  - *Use this when:* A new project idea or feature proposal is ready to be explored
  - *Key deliverables:* Project One-pager, stakeholder list, high-level timeline, risk list

### 2. Planning
- **[Project Planning](octoacme-project-planning.md)** — Break work into shippable increments, estimate, and define milestones
  - *Use this when:* An initiative has been approved and is ready to become an actionable plan
  - *Key deliverables:* Prioritized backlog, release plan, Definition of Done, risk register

### 3. Execution & Tracking
- **[Execution & Tracking](octoacme-execution-and-tracking.md)** — Day-to-day team rhythm, PR workflow, quality standards
  - *Use this when:* Managing daily execution, sprint planning, and progress tracking
  - *Key cadence:* Daily standups (15 min), weekly delivery sync, demo/review at milestone end

### 4. Risk & Communication
- **[Risk Management & Communication](octoacme-risks-and-communication.md)** — Maintain risk register, escalate blockers, update stakeholders
  - *Use this when:* Identifying and managing risks, communicating status to stakeholders
  - *Key outputs:* Risk register, weekly status updates, escalation paths

### 5. Release & Deployment
- **[Release & Deployment Guide](octoacme-release-and-deployment.md)** — Standardize releases, deployment checklists, rollback procedures
  - *Use this when:* Preparing features for production deployment
  - *Key steps:* Pre-release requirements, deployment checklist, post-deploy verification

### 6. Close & Improve
- **[Retrospective & Continuous Improvement](octoacme-retrospective-and-continuous-improvement.md)** — Capture learnings and drive improvements
  - *Use this when:* After each sprint, release, or important milestone
  - *Key activity:* Retrospective meeting (45–75 min), action item tracking, impact measurement

## Core Principles

- **Customer-first**: Prioritize customer value and usability
- **Iterative delivery**: Deliver small, testable increments
- **Clear ownership**: Each project has named PM and Product Lead
- **Data-informed decisions**: Measure impact and iterate based on evidence
- **Psychological safety**: Encourage feedback and learning

## Key Roles at a Glance

| Role | Responsibilities | Key Goals |
|------|------------------|-----------|
| **Product Manager** | Define outcomes, prioritize backlog, measure success | Maximize customer value and impact |
| **Project Manager** | Coordinate delivery, manage schedules and risks, facilitate communication | Deliver on time and within scope |
| **Developers** | Implement features, write tests, collaborate on design | Deliver reliable, maintainable code |
| **QA/Testing** | Validate quality and acceptance criteria | Ensure feature acceptance |

## Communication Cadence

- **Daily**: 15-minute standups (progress, blockers, dependencies)
- **Twice-weekly**: Delivery team standups
- **Weekly**: PM + PdM sync; status updates to stakeholders
- **Monthly**: Stakeholder briefings
- **Ad-hoc**: Escalations and incident communications
